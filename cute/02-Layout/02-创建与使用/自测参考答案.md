# Layout 创建与使用：自测参考答案

> 对应：[Layout 创建与使用](README.md#8-本节自测)
>
> 更新：2026-09-11

## 1. 省略 Stride 时的默认方向

`make_layout(shape)` 默认使用 `LayoutLeft`，不是 `LayoutRight`：

```cpp
make_layout(make_shape(M, N))
```

对于普通 depth-1 二维 Shape，结果为：

```text
(M,N):(1,M)
```

这通常对应 column-major。

如果希望生成普通 row-major Layout，需要显式指定：

```cpp
make_layout(make_shape(M, N), LayoutRight{})
```

结果为：

```text
(M,N):(N,1)
```

## 2. 为什么 `((4,2)):((2,1))` 是 vector

它是 vector，因为它的顶层 rank 为 1：

```text
Shape = ((4,2))
```

最外层 tuple 只有一个 mode；这个 mode 内部又包含 `(4,2)` 两个子 mode。

因此：

```text
rank  = 1
depth = 2
size  = 8
```

判断 vector 或 matrix 看的是顶层 rank，不是 size，也不是能否 coalesce：

```text
rank == 1  -> vector
rank == 2  -> matrix
```

该 Layout 的一维 index 序列是：

```text
0,2,4,6,1,3,5,7
```

所以它不能等同于 `8:1`。容易与它混淆的是：

```text
((4,2)):((1,4))
```

后者的一维映射才是：

```text
0,1,2,3,4,5,6,7
```

## 3. 为什么层级 Shape 不能简单套用 row-major 直觉

`LayoutRight` 生成 Stride 时，会跨越括号层级，对所有叶子 Shape 从右向左计算 exclusive prefix product，然后恢复原有 tuple profile。

例如：

```text
Shape = ((2,3),4)
```

先观察叶子：

```text
2,3,4
```

从右向左生成：

```text
12,4,1
```

恢复层级：

```text
Shape  = ((2,3),4)
Stride = ((12,4),1)
```

如果只把顶层 Shape 看成普通的 `(6,4)` 矩阵，可能会预期 row-major stride 是：

```text
(4,1)
```

但第一个顶层 mode 实际是 multi-mode，它内部具有 `(12,4)` 两个 stride。其内部坐标顺序不一定等于普通长度为 6 的线性行坐标。

因此，对层级 Shape 应先展开叶子、计算 stride，再恢复层级，不能只根据顶层大小猜测。

## 4. 二维表格与一维自然序的区别

对于：

```text
L = (4,2):(2,1)
```

使用 `(m,n)` 展示成二维表格：

```text
       n=0  n=1
m=0    0    1
m=1    2    3
m=2    4    5
m=3    6    7
```

这个表格按行展示坐标位置：外层观察 `m`，每行中横向观察 `n`。

CuTe 的一维自然序则让 mode-0，也就是 `m`，最先变化：

```text
(0,0), (1,0), (2,0), (3,0),
(0,1), (1,1), (2,1), (3,1)
```

对应的 index 序列是：

```text
0,2,4,6,1,3,5,7
```

所以二者的“输出排列顺序”不一致，但描述的是同一个 Layout 映射：

```text
二维表格：按坐标几何形状展示
一维自然序：按 mode-0 最先变化的顺序枚举
```
