# 坐标与兼容性：自测参考答案

> 对应：[坐标与兼容性](README.md#11-本节自测)
>
> 更新：2026-09-11

## 1. 三种坐标分别是什么

对于：

```text
Shape = (3,(2,3))
```

三种坐标分别是：

```text
一维坐标：
  i
  0 <= i < 18

rank-D 坐标：
  (m,n)
  0 <= m < 3
  0 <= n < 6

自然坐标：
  (m,(p,q))
  0 <= m < 3
  0 <= p < 2
  0 <= q < 3
```

其中：

```text
size((2,3)) = 6
```

所以 rank-D 坐标会把第二个顶层 multi-mode `(2,3)` 暂时看成一个大小为 6 的 mode。

## 2. 为什么 `idx2crd` 不只是“一维下标转二维坐标”

因为输出维度和层级由 Shape 决定，不一定是二维。

例如：

```text
Shape = (2,3,4)
```

输出可能是三维自然坐标：

```text
(i,j,k)
```

对于层级 Shape：

```text
Shape = (3,(2,3))
```

输出可能是层级自然坐标：

```text
(m,(p,q))
```

此外，`idx2crd` 的输入也不一定是一个标量。它可以把与目标 Shape compatible 的坐标归一化为与 Shape congruent 的自然坐标：

```text
idx2crd(16,       (3,(2,3))) = (1,(1,2))
idx2crd((1,5),    (3,(2,3))) = (1,(1,2))
idx2crd((1,(1,2)),(3,(2,3))) = (1,(1,2))
```

## 3. `crd2idx` 的两个概念步骤

如果输入已经是与 Shape congruent 的自然坐标，确实可以直接与对应 Stride 相乘并求和。

但 `crd2idx` 接受的输入不一定已经是自然坐标，因此完整过程是：

```text
第一步：通过 idx2crd 将输入转换为自然坐标
第二步：将自然坐标与 Stride 做内积
```

例如：

```text
Shape  = (4,3)
Stride = (3,1)
输入   = 5
```

第一步：

```text
idx2crd(5, (4,3)) = (1,1)
```

第二步：

```text
crd2idx(5, (4,3), (3,1))
  = 1*3 + 1*1
  = 4
```

如果输入本来就是 `(1,1)`，第一步不需要改变其结构，随后直接进行内积。

## 4. 为什么 `layout(i)` 不总等于 `i * stride<0>`

多 mode 或层级 Layout 中，标量 `i` 是整个 Shape 的一维自然序号，不是 mode-0 的坐标。

必须先执行：

```text
i -> idx2crd(i, shape)
```

然后让得到的每个自然坐标分量分别乘对应 Stride。

例如：

```text
L = (4,2):(2,1)
i = 4
```

正确计算：

```text
idx2crd(4, (4,2)) = (0,1)
L(4) = 0*2 + 1*1 = 1
```

直接计算：

```text
4 * stride<0> = 4*2 = 8
```

会错误地把整个一维序号都当成 mode-0 坐标。

问题的根本原因是**多 mode 坐标分解**，不是地址是否存在空洞；即使 Layout 没有空洞，也不能省略该分解。

## 5. 为什么相同 size 不能保证 compatible

相同 size 是 compatibility 的必要条件之一，不是无关的副产品：

```text
compatible(A,B)
要求：
1. size(A) == size(B)
2. A 的所有坐标形式都能作为 B 的有效坐标
```

相同 size 只说明二者拥有相同数量的逻辑位置，没有说明坐标层级是否兼容。

例如：

```text
size((24)) = size(24) = 24
```

但：

```text
24 ~ (24)       # true
(24) ~ 24       # false
```

原因是 `(24)` 还具有 `(i)` 形式的 tuple 自然坐标，而标量 Shape `24` 没有相应的 tuple 层级。

## 6. `size`、像集大小和 `cosize`

三者回答不同问题：

| 概念 | 回答的问题 |
|---|---|
| `size` | 定义域中有多少个逻辑坐标？ |
| 像集大小 | Layout 实际产生了多少个不同的 index？ |
| `cosize` | 按官方定义，Layout 的 codomain size 是多少？ |

像集是 Layout 输出 index 去重后的集合，不是逻辑位置的集合：

```text
range(L) = { L(c) | c 是合法逻辑坐标 }
```

例如：

```text
L = (2,2):(0,3)
index 序列 = 0,0,3,3
```

则：

```text
size(L)        = 4
range(L)       = {0,3}
像集大小       = 2
cosize(L)      = L(3)+1 = 4
```

在常见的非负 Stride 场景，可以把 `cosize` 辅助理解为从 0 开始需要覆盖的 index 区间大小，但它不等于像集大小。

## 7. 能否同时存在地址重叠和地址空洞

可以。

例如：

```text
L = (2,2):(0,3)
index 序列 = 0,0,3,3
```

- `0` 和 `3` 都被重复访问，因此存在地址重叠；
- `[0,4)` 中的 `1` 和 `2` 没有被访问，因此存在地址空洞。

## 8. 像集连续能否推出单射

不能。

例如：

```text
index 序列 = 0,1,1,2
像集       = {0,1,2}
```

像集没有空洞，所以像集连续；但 index `1` 被两个不同坐标命中，因此 Layout 不是单射。

需要分别判断：

```text
像集连续：有没有空洞
单射：    有没有重复
```
