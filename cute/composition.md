# Composition 的循环视角

> 目标：把 CuTe Layout 的 composition（`R = A ∘ B`）翻译成**嵌套循环**的语言来理解。
> 本文所有数值结果均经 NVIDIA CuTe DSL 实跑验证。

---

## 0. 预备：Layout 就是一段循环

一个 Layout `S:D` 描述的是「坐标 → offset」的映射。但更直观的看法是：**它描述了一段嵌套循环的遍历方式**。

CuTe 的自然序是 **column-major（mode-0 变化最快）**，对应到循环：

> **mode-0 = 最内层循环；mode 号越大，循环越靠外。**

例如 `(4,5):(1,4)`：

```c
for (j = 0; j < 5; j++)        // mode-1, stride 4   ← 外层
  for (i = 0; i < 4; i++)      // mode-0, stride 1   ← 内层
    offset = 1*i + 4*j;
```

内层走一遍：`0, 1, 2, 3`，**跨度** `4 × 1 = 4`
外层每步进：`+4`

**外层的步长，正好等于内层走完一整遍的跨度** → 两层严丝合缝，可以拍平成一个循环：

```c
for (k = 0; k < 20; k++) offset = k;    // 20:1
```

## 0.5 回顾：Coalesce 就是「两层循环能否拍平」

设内层 mode 为 `s0:d0`，外层 mode 为 `s1:d1`：

| 循环概念 | 公式 | 含义 |
|---|---|---|
| 内层步长 | `d0` | 内层每迭代一次跳多远 |
| 内层跨度 | `s0 * d0` | 内层跑完一整遍后，下一格在哪 |
| 外层步长 | `d1` | 外层每迭代一次跳多远 |

**拍平条件：`d1 == s0 * d0`**

拍平后单循环的步长就是 **`d0`**（内层步长）—— 这就是为什么 coalesce 合并时 stride 直接抄 `d0`，不需要任何计算。

### 三种情况

| 情况 | 循环含义 | 结果 |
|---|---|---|
| `d1 == s0*d0` | 外层恰好接在内层走完的位置 | ✅ 可合并 |
| `d1 > s0*d0` | 外层跳太远，中间**有空洞** | ❌ 保持不动 |
| `d1 < s0*d0` | 外层落在内层跨度**之内**，offset 撞车（非单射） | ❌ 保持不动 |

**退化情况**：若 `s0 == 1` 或 `s1 == 1`，该层循环只跑一次，对顺序无贡献 → **整个删掉，它的 stride 也一起消失**（不会累加到邻居）。

### 为什么行主序合不了

`(4,5):(5,1)` 写成循环：

```c
for (b = 0; b < 5; b++)      // mode-1, stride 1  ← 外层
  for (a = 0; a < 4; a++)    // mode-0, stride 5  ← 内层
    offset = 5*a + 1*b;
```

内层跑一遍：`0, 5, 10, 15`（跨度 `4×5 = 20`），外层每步 `+1`。`1 ≠ 20` → 判据不成立。

从循环角度说：**这里是外层在连续扫内存（+1），内层在跳（+5）**。想拍平成一个循环，拍出来的顺序是 `0,1,2,3,4,...`，而原顺序是 `0,5,10,15,1,6,...` —— **顺序变了，函数就变了**。

> Coalesce 的拍平只能按自然序（mode-0 最快）进行，它**不会**帮你交换循环。要拍平行主序，得先做 `permutation`，那是另一个操作。

## 1. 第一层翻译：谁提供循环，谁提供数值

复合 `R = A ∘ B`，定义 `R(c) = A(B(c))`。翻译成循环：

```c
// B 提供"循环骨架"（shape 来自 B）
for (q = 0; q < 3; q++)        // B 的 mode-1，外层
  for (p = 0; p < 4; p++)      // B 的 mode-0，内层
    n = 3*p + 1*q;             // B 的输出：一个自然数
    offset = A(n);             // A 的作用：拿这个数去查表
```

**一句话分工**：

- **B 决定循环长什么样**（几层、每层几次）—— B 是右函数，定义定义域
- **A 决定循环体里算出什么 offset** —— stride 的来源

Composition 的全部难度就是一件事：

> **A 是一个「查表」，但我们要的是一个「能直接算的循环」。**
> `/d` 和 `%s` 就是把查表翻译成显式循环的两步。

---

## 2. 左分配律：按 B 的 mode 拆开

复合对 concatenation 满足左分配律：

```
A ∘ (B0, B1, ...) = (A ∘ B0, A ∘ B1, ...)
```

循环含义：**B 的每一层循环各算各的，互不干扰**。所以我们可以把 B 拆成一堆单 mode 的 `s:d`，逐个处理再拼回去。

于是问题归约为：

> **`A ∘ s:d` 怎么算？**
> 其中 `s` = 该层循环的 trip count，`d` = 该层每步让 `n` 增加多少。

---

## 3. 第二层：`/d` = 对 A 做「隔 d 个取一个」

B 的某个 mode 是 `s:d`，意思是：这个循环变量每 +1，输出 `n` 就 **+d**。

从 A 的视角看：我不需要 A 的全部元素，我只需要 A 自然序里的**第 0, d, 2d, 3d, ... 个**。这就是**隔 d 个取一个**（strided sampling）。

### 例子

A = `(6,2):(8,2)`，mode = `4:3`（d = 3）：

```
A 的自然序 n:  0   1   2   3   4   5   6   7  ...
A(n):          0   8  16  24  32  40   2  10  ...
               ↑           ↑           ↑
               隔 3 取 1 →  0,  24,  2,  26
```

写成循环：

```c
// 原来（走 6 步，每步 +8）
for (a = 0; a < 6; a++)  offset = 8*a;      // 0, 8, 16, 24, 32, 40

// 隔 3 取 1 之后（走 2 步，每步 +24）
for (a = 0; a < 2; a++)  offset = 24*a;     // 0, 24
```

**这就是 `/d`：trip count ÷ d，stride × d。**

### 关键不变量：总跨度不变

```
6 × 8 = 48        2 × 24 = 48
```

`/d` **不改变这个 mode 覆盖的范围**，只改变采样密度 —— 同样一段路，原来走 6 步，现在跨 3 格走 2 步。

### d 太大时：跨 mode 吃

如果 d 超过了 mode-0 的 shape，mode-0 整个被"吃完"，剩下的商继续吃 mode-1。

实测 `(6,2):(8,2) ∘ 2:6`（d = 6）：

```
mode-0: 6/6 = 1（吃完），剩余 d = 1 → mode-1: 2/1 = 2
stride: (8*6, 2) = (48, 2)
→ (1,2):(48,2) → coalesce 删掉 shape=1 → 2:2
```

验证：`R(0) = A(0) = 0`，`R(1) = A(6) = 2` ✓ —— 正好是 A 隔 6 取 1。

---

## 4. 第三层：`%s` = 把 trip count 截到 s

`/d` 之后，循环能跑 `size(A)/d` 次。但 B 的这个 mode 只要 **s 次**：

```c
for (k = 0; k < size(A)/d; k++) ...   // 太多
for (k = 0; k < s; k++) ...           // 只要 s 次
```

**截断，而且 stride 一个都不改** —— 截断只是"少跑几圈"，每圈跳多远当然不变。

### `%s` 的确切规则（贪心、逐 mode）

从左到右遍历 mode，维护剩余额度 `rem`（初始 = `s`）：

```
第 i 个 mode 取：  s_i' = min(s_i, rem)
更新额度：        rem  = rem / s_i'
```

额度一旦变成 1，后面所有 mode 都只能取 1（coalesce 时这些 1 会被删掉）。

因为截断按 A 的自然序（column-major）从前往后取，所以**可能切在某个 mode 中间，那个 mode 就被劈开**。

### 实测例子

`(6,2):(8,2) ∘ 3:1`（d = 1，s = 3）：

```
/1:  还是 (6,2):(8,2)，能跑 12 次，但 s = 3
%3:  mode-0 取 min(6,3) = 3，额度 3/3 = 1 → mode-1 只能取 1
→ (3,1):(8,2) → coalesce 删掉 size-1 → 3:8
```

验证：`R(0)=A(0)=0`，`R(1)=A(1)=8`，`R(2)=A(2)=16` ✓ —— 就是 A 的前 3 个。

### 三种情况

| `/d` 之后的 size | `%s` 干什么 |
|---|---|
| `== s` | 恒等（取前 s 个 = 取全部） |
| `> s` | 截断，可能劈开某个 mode |
| `< s` | 元素不够喂，CuTe 的前置条件会拦下 |

> **注意**：`%s` 的本质始终是「按 column-major 取前 s 个、重排 shape、绝不碰 stride」。size 恰好等于 s 时它退化为恒等，但那是"恰好等价"，不是"规则在偷懒"。

---

## 5. 第四层：拼回去 = 重建 B 的循环嵌套

B 有几层，R 就有几层（每个 mode 各自复合、再按 B 的结构拼回去）。

最终循环骨架和 B 长得一样，**只是每个循环体的 offset 变了**。

这保证了核心后置条件：**`compatible(B, R)`** —— B 的每个坐标都能用在 R 上。


** 总结：/d 让 A 学会"按 B 的步子走"，%s 让 A 学会"只走 B 要求的那么多步"，最后按 B 的套数组装回去。 **

## 6. 完整走一遍官方例子

```
A = (6,2):(8,2)
B = (4,3):(3,1)
```

### B 的循环骨架

```c
for (q = 0; q < 3; q++)       // mode-1，外层
  for (p = 0; p < 4; p++)     // mode-0，内层
```

### 分支 1：`A ∘ 4:3`（内层，d = 3，s = 4）

- `/3`：A 隔 3 取 1 → mode-0 走 2 步、每步 24；mode-1 不动
  ```
  (6/3, 2) : (8*3, 2) = (2,2):(24,2)
  ```
- size = 4 = s → `%4` 恒等
- 结果：`(2,2):(24,2)`

**循环含义**：内层 p 从 0 到 3 需要 4 个点，A 隔 3 取 1 正好供给 4 个。但这 4 个点**来自 A 的两个不同 mode**（前两个在 A 的 mode-0，后两个跳到 A 的 mode-1），一个循环描述不了，只能拆成两层 → 这就是结果里 `(2,2)` 的来源。

### 分支 2：`A ∘ 3:1`（外层，d = 1，s = 3）

- `/1`：不变，`(6,2):(8,2)`
- `%3`：截到 3 次 → `(3,1):(8,2)` → coalesce → `3:8`
- 结果：`3:8`

### 拼回去

```
R = ((2,2), 3) : ((24,2), 8)
```

对应的循环：

```c
for (q = 0; q < 3; q++)            // 外层，步长 8
  for (b = 0; b < 2; b++)          // 内层的外层，步长 2
    for (a = 0; a < 2; a++)        // 内层的最内层，步长 24
      offset = 24*a + 2*b + 8*q;
```

**内层被"撑"成了两层** —— 因为 A 隔 3 取 1 时，取的点跨过了 A 自己的 mode 边界。

> 这是 composition 结果中出现**嵌套 shape** 的根本原因。

### 逐点验证

| i | B(i) | A(B(i)) | R 计算式 |
|---|---|---|---|
| 0 | 0 | 0 | (0,0,0) → 0 ✓ |
| 1 | 3 | 24 | (1,0,0) → 24 ✓ |
| 2 | 6 | 2 | (0,1,0) → 2 ✓ |
| 3 | 9 | 26 | (1,1,0) → 26 ✓ |
| 4 | 1 | 8 | (0,0,1) → 8 ✓ |
| 5 | 4 | 32 | (1,0,1) → 32 ✓ |
| 6 | 7 | 10 | (0,1,1) → 10 ✓ |
| 7 | 10 | 34 | (1,1,1) → 34 ✓ |
| 8 | 2 | 16 | (0,0,2) → 16 ✓ |
| 9 | 5 | 40 | (1,0,2) → 40 ✓ |
| 10 | 8 | 18 | (0,1,2) → 18 ✓ |
| 11 | 11 | 42 | (1,1,2) → 42 ✓ |

## 7. 对照表

| 操作 | 循环语言 | 具体动作 | 不变量 |
|---|---|---|---|
| `/d` | 隔 d 个取一个 | trip ÷ d，stride × d | **总跨度不变** |
| `%s` | 只要前 s 次迭代 | 从左到右截 shape | **stride 不动** |
| 拼接 | 重建 B 的嵌套结构 | 按 B 的 mode 分组 | shape 与 B 兼容 |
| coalesce | 相邻两层能否拍平 | `d1 == s0*d0` 则合并，stride 抄 `d0` | 遍历顺序不变 |

---

## 8. 一句话总结

> **把 A 看成一个数组：**
> `/d` 是**按步长 d 采样**（trip count ÷ d，stride × d，总跨度不变）；
> `%s` 是**取前 s 个采样点**（截断 shape，stride 不动）；
> 最后**套上 B 的循环嵌套**（B 有几层，R 就有几层）。

Coalesce 则是在问：**这两层嵌套循环能不能在不改变遍历顺序的前提下写成一个循环？**
答案是：**当且仅当 `外层步长 == 内层 size × 内层步长`。**

## 附：常见误区

1. **合并时 stride 是抄来的，不是算出来的。** `s0:d0 ++ s1:d1 → s0*s1:d0`，stride 取 `d0`，不做乘除。
2. **contiguous ≠ coalescable。** 行主序的紧凑矩阵压不成一条，因为拍平会改变遍历顺序。
3. **coalesce 不保结构。** 它会跨层级括号合并（例如 `((2,2),2):((1,3),6)` → `(2,4):(1,3)`），如果需要保留 mode 边界，用 **by-mode coalesce**。
4. **`%s` 不碰 stride。** 截断只影响 shape。
5. **`/d` 不改总跨度。** 它只改变采样密度。
