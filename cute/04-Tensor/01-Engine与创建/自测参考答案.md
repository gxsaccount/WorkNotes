# Engine 与 Tensor 创建：自测参考答案

> 对应：[Engine 与 Tensor 创建](README.md#11-本节自测)
>
> 更新：2026-09-15

## 1. Engine 与 Layout 的职责

```text
Layout：把逻辑坐标映射为 offset
Engine：保存或引用能够按 offset 随机访问的数据
Tensor：用 Layout 的输出访问 Engine
```

概念公式为：

```text
tensor(coord) = engine[layout(coord)]
```

## 2. `make_gmem_ptr` 的作用

它不分配显存，也不搬运数据，只把现有 iterator 标记为 global-memory iterator。标签让算法能够检查地址空间，并选择适用的专用实现。

## 3. Nonowning Tensor 为什么允许动态 Layout

因为它只引用已经存在的数据，不需要根据 Layout 在 Tensor 对象内部创建数组。动态 Shape 或 Stride 只影响运行时如何计算 offset。

## 4. Owning Tensor 为什么要求全静态

owning Tensor 的内部容量类似 `std::array<T,N>`，必须在编译期成为类型的一部分。Shape 或 Stride 动态时，所需的 `cosize` 无法作为固定数组容量确定。

## 5. `size` 与 `cosize`

- `size(layout)`：逻辑坐标总数；
- `cosize(layout)`：覆盖 Layout 所访问 offset 所需的 codomain 范围。

紧凑单射 Layout 中二者常相等；带 padding 或空洞时，存储容量可能需要按 `cosize` 而不是 `size` 准备。

## 6. 按值接收 Tensor 的风险

Tensor 可能是：

- nonowning view：复制只复制 iterator 和 Layout；
- owning array：复制会深拷贝内部元素。

泛型函数若按值接收，成本会随具体 Engine 语义变化，因此输入通常按 `const&` 或 `&` 传递。

## 7. `make_tensor_like` 是否复制完整 Stride

不保证。它保证新 Tensor 拥有相同 value type 和 Shape，并尝试保留 stride 的相对顺序，但可能生成紧凑 Layout，去掉原来的 padding。
