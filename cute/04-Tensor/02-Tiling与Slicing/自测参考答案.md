# Tensor Tiling 与 Slicing：自测参考答案

> 对应：[Tensor Tiling 与 Slicing](README.md#10-本节自测)
>
> 更新：2026-09-15

## 1. Tensor tiling 是否移动数据

不会。它对 Tensor 的 Layout 做 composition 或 division，产生新的坐标组织方式；结果仍然引用相关 Engine。实际数据搬运需要 `copy` 等算法。

## 2. Tensor 为什么没有 product

Layout product 可能扩大 codomain，使新 Layout 产生超出旧 Tensor 数据范围的 offset。纯 Layout 可以表示这种函数，但 Tensor view 无法一般性地保证这些访问安全。

## 3. 固定坐标与 `_` 的作用

- 固定坐标：通过原 Layout 计算 offset，并累加到新 iterator；
- `_`：保留相应 mode 的 Shape、Stride 和层级，用来构造结果 Layout。

最终结果为：

```text
subtensor = shifted_engine + retained_layout
```

## 4. `C` 与 `D` 为什么 Shape 不同

```cpp
C = A(_, 5);
D = A(make_coord(_,_), 5);
```

`C` 使用一个 `_` 保留整个复合 mode，因此顶层 rank 为 1；`D` 使用两个 `_` 分别保留其中两个子 mode，因此顶层 rank 为 2。二者固定部分相同，所以元素集合相同。

## 5. `E` 与 `F` 的 base offset

原映射：

```text
offset = 4*m0 + m1 + 2*n0 + 13*n1 + 100*n2
```

对于：

```cpp
E = A(make_coord(_,1), make_coord(0,_,1));
```

固定贡献：

```text
1 + 0 + 100 = 101
```

对于：

```cpp
F = A(make_coord(2,_), make_coord(_,3,_));
```

固定贡献：

```text
2*4 + 3*13 = 47
```

## 6. 为什么 tile Shape 必须静态

`make_tensor_like` 创建 owning register Tensor，其内部容量必须在编译期确定。若 subtensor Shape 动态，就无法形成固定大小的内部数组类型。

## 7. 三种操作的分工

```text
zipped_divide -> 将坐标重组为 (tile, rest)
slicing       -> 选择一个 tile，得到 view
copy          -> 把 view 中的元素实际搬入寄存器 Tensor
```
